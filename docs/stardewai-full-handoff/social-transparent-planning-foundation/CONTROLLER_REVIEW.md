# Controller Review: Required Before Commit

Resolve every blocker below. Decompiled vanilla source is authoritative; the scout summary is not.

1. **The current implementation can never emit a social candidate.** `NpcReadAdapter` hard-codes `can_socialize_complete=false`, `can_receive_gifts_complete=false`, `current_route_window_complete=false`, and makes all `gift_tastes` unavailable. This is honest but does not implement the requested current-state foundation. Decompiled `NPC.CanSocialize`/`CanSocializePerData`, `CanReceiveGifts()`, `isBirthday()`, and `getGiftTasteForThisItem(Item)` are read/query paths; verify their complete bodies and use the exact side-effect-free live result for loaded NPCs and currently owned eligible items. If any subtype/modded override cannot be proven pure, fail that row closed with runtime type/provenance rather than disabling every vanilla row.

2. **Controller/movement is not a universal interaction block.** Vanilla `NPC.checkAction` does not reject every NPC with `controller != null` or `isMoving()`. The `controller == null` branch shown by the scout is a Henchman special case. Remove `has_controller` and broad `is_busy` from universal talk/gift blockers. Inventory the actual general and special-case gates from the complete `checkAction`/`tryToReceiveActiveObject` branches and represent unsupported special NPCs separately.

3. **An adjacent open tile is not route reachability.** `AdjacentStandTileAvailable` only finds a non-notable neighboring tile. It does not prove the player can reach it and treats missing/incomplete collision grids too loosely. Reuse the repository's collision/path/compiler probe semantics to select an exact reachable stand tile from the player's current tile, including current map bounds and blockers. Preserve stand tile in candidate parameters. Fail closed when route data is incomplete.

4. **Do not erase blocked diagnostics.** `Build(...).Where(candidate.Available)` plus returning `null`/`yield break` removes the exact reason an NPC/item was excluded. Candidate scoring must receive only available rows, but the availability/transparency response still needs bounded blocked-row diagnostics or an explicit exclusion summary grouped by stable reason. Missing taste/schedule/route fields must remain observable to audits.

5. **Gift outcome math must be exact or unavailable.** Reproduce all deterministic inputs used by `receiveGift`: taste including Stardrop Tea and universal/NPC/tag exceptions, item quality multiplier, birthday multiplier, spouse-giver halving, cap/special cases, and relationship/limit branches. Do not emit `expected_friendship_delta` unless every applicable deterministic branch is covered. Dialogue randomness is not required for friendship delta but must be labeled separately.

6. **Talk semantics need exact output classification.** `TalkedToToday` changes whether `grantConversationFriendship` awards points; statue buff and divorce alter the delta, and special NPC/shop/quest/event branches can replace ordinary talk. Preserve expected ordinary talk delta only when complete, otherwise classify the candidate as unsupported/unknown. Do not claim every `checkAction` is a normal friendship talk.

7. **Gift versus quest/special delivery must fail closed.** `tryToReceiveActiveObject(probe:true)` has a vanilla probe contract but traverses quest/special-order delegates and many special item/NPC branches. Do not invoke it from the transparent observer unless the complete call chain is proven side-effect-free for the current context. Conservatively exclude active quest/special-order ambiguity and unsupported special branches with explicit reasons.

8. **No guessed zero duration/cost.** Social route and native executor timing are unknown in this slice. Keep candidates unavailable for ranking/training until exact current route and executor cost semantics exist, or carry explicit unknown sentinels plus a hard block. Do not let numeric zero look like a free action.

9. **Normal-gift limits have explicit vanilla exceptions.** The complete `tryToReceiveActiveObject` normal-gift branch allows the weekly gate for spouse, `Child`, birthday, and `(O)StardropTea`, not birthday alone. Stardrop Tea also bypasses the ordinary second-gift-today rejection and calls `receiveGift(..., updateGiftLimitInfo:false)`, so it must not predict normal gift-counter increments. Encode these exact branches or fail the row closed.

10. **Missing friendship is not automatically illegal.** For a valid normal gift, vanilla creates a new `Friendship` when the row is absent. Do not globally reject `social_friendship_missing`; represent the deterministic zero-point/counter baseline and friendship-row creation only where the complete ordinary branch is proven. The same `checkAction` path may initialize friendship before ordinary social dialogue.

11. **Inventory giftability and world-state gates must match the full branch.** Require `activeObj.canBeGivenAsGift()` and absence of the sanitized `not_giftable` base tag. Account for year-one Green Rain/non-married rejection and active `dumped` dialogue-event rejection. Special switch items (movie ticket, bouquet, pendant/proposals, quest/special items, NPC-specific items such as the Henchman/Pierre/Jas branches) and roommate-proposal context tags are not ordinary gifts; exclude them explicitly unless separately modeled.

12. **Friendship modifiers are deterministic, not unknown.** `Farmer.changeFriendship` applies the Book of Friendship positive 1.1 multiplier, Dwarvish-language positive suppression, divorced positive suppression, spouse 0.66 multiplier, and clamping. Compute them from transparent live fields when available; do not mark every Book/Dwarf case incomplete. Keep jealousy as a separate stochastic side effect/output-risk label rather than folding it into the target NPC's deterministic gift delta.

13. **Special item inventory must match the decompiled switch.** The inspected `tryToReceiveActiveObject` switch includes `(O)233`, `(O)897`, `(O)71`, `(O)864` through `(O)870`, `(O)809`, `(O)458`, `(O)277`, and `(O)460`, plus the default roommate-proposal context-tag branch. The current partial exclusion list is not complete. Model each context exactly or exclude the item from ordinary gifting with a stable special-branch reason; do not allow it to fall through as a normal gift.

14. **Malformed route coverage must fail closed.** A missing or malformed `locations.route_action_branch_coverage` cannot become an empty set of unsupported tiles. Require readable collision-grid and action-coverage envelopes/shape before BFS, and preserve a route-data-incomplete block reason. Verify the chosen stand tile and route remain bound in compiler parameters.

15. **Unknown social cost must not serialize as zero.** Both social candidate constructors set `EstimatedTicks = -1` but leave `EnergyCost` at the contract default `0`. Set an explicit unknown sentinel for energy/cost as well, keep the option preview-only and executor-blocked, and add a focused assertion so neither ranking nor training can mistake this slice for a free action.

16. **Missing giftability facts must fail closed.** `AddItemBlockReasons` currently blocks `can_be_given_as_gift` only when it is explicitly `false`; a missing/non-boolean property falls through. It also treats a missing/non-boolean `base_tag_not_giftable` as `false`. Require both fields with the expected boolean shape before an ordinary gift candidate can be available, and test missing/malformed forms.

17. **Validate every route/collision row, not only the outer envelope.** `ReadUnsupportedRouteActionTileKeys` currently ignores non-object rows and silently maps missing/non-numeric coordinates through `ReadInt(...)=0`. `ReadBlockedCollisionTileKeys` has the same coordinate-shape weakness. Any malformed row or out-of-bounds coordinate must make route evidence incomplete; do not partially consume it. Add row-shape and coordinate tests.

18. **Current-position planning must not require a loaded future schedule.** For an NPC loaded in the player's current location, exact current tile plus collision facts are sufficient for this current-state preview. Do not universally block because `schedule_loaded` is false, and do not label a hard-coded `current_route_window_complete=true` as future-route completeness. Preserve explicit provenance that future schedule projection is not emitted.

19. **Exercise the whole special-item switch inventory.** The implementation list now appears complete, but the test covers only `(O)809`. Add a parameterized/static test over `(O)233`, `(O)897`, `(O)71`, `(O)864`-`(O)870`, `(O)809`, `(O)458`, `(O)277`, and `(O)460`, plus the roommate context-tag branch.

Add focused tests for each correction, but do not execute them while the user is playing. Re-read `TASK.md`, `ACCEPTANCE.md`, and this file before static review and commit.
