# 任务驱动机器容量 EVD-217 短交接

状态：静态实现、隐藏静默运行矩阵与 EVD-217 证据登记完成；同一能力的有界任务范围已训练准入。

本切片扩展既有 `farm.establish_supported_machine_capacity`，没有新增第二套机器执行系统。精确普通 `ResourceCollectionQuest` 或特别订单 `CollectObjective` 若只能由当前快照中确定性、零附加耗材的机器产物满足，可形成一个容量需求。已有摆放机器或背包机器会抵消需求；背包已有机器直接进入既有摆放链，否则进入既有制作链。后续摆放、任务投料、自然处理和收取继续复用现有链，并由同一个 `MachineSupportIntent` 持久化。

已闭合的失败边界：

- 任务来源必须是规范化、去重排序的精确普通收集任务或特别订单来源；
- 机器本体 ID 不能冒充机器产物需求；
- 浣熊请求、`CraftingQuest`、混合来源、随机产物、附加耗材和远程机器不进入本范围；
- 无关材料预留只有在精确槽位余量足够时才可通过，同槽冲突必须阻断；
- 任务消失或来源变化后，摆放与编译必须阻断；
- 任务漂移、混合来源、附加耗材和精确槽位冲突由静态编译/账本测试失败关闭。

运行证据：普通任务制作 `runtime-supported-machine-capacity-evd217-final2-ordinary-20260805`、特别订单制作 `runtime-supported-machine-capacity-evd217-final-special-20260805`、背包机器直接摆放 `runtime-supported-machine-capacity-evd217-final2-inventory-20260805` 均通过。三条路径均使用既有原生摆放、投料、自然处理和收取；投料后进度为 `0/1`，原生收取后为 `1/1`。首次直摆运行暴露远程路线抢占问题，入口收紧到当前地图 `place_machine_item` 后通过；最终重跑还锁定了队列 ID 数组格式和直摆意图的 `fleet=0:required=1` 身份。

本证据没有扩大到远程机器、随机产物、附加耗材、浣熊请求或混合任务来源，也不代表正式全量训练已经就绪。下一切片应从权威依赖树中选择仍未训练准入的既有动作族，不得再为机器容量建立第二套入口。
