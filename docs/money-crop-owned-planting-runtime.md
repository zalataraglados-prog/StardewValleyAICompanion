## Before Mutation And Each Dispatch

Read-only preflight replays the original marker service, builds the original
claim-bounded batch and runs the original compiler before any real mutation.
The actual transparent current_location.planting_context must uniquely identify
each target tile, exact selected seed slot, native planting permission and the
same unboosted base-growth profile as the crop commitment. Missing/ill-typed data,
fertilizer/agriculturist/paddy speed modifiers or adjusted timing drift stop here.
The native rule source remains HoeDirt.applySpeedIncreases; the existing bridge
already publishes the effective with/without-paddy boosts and adjusted growth.
No new game constants, phase simulator or bridge snapshot producer is introduced.

Only the real marker reply and full readback authorize the actual compilation.
Its intent records requested/bounded batches and the selected reservation ID.
The original maximum-eight mechanical batch is retained; do not split it into
single-seed queues to avoid source changes. The explicit control profile requires
isolated singleplayer, no executor override/preference rebind, queue receipts and
a maximum attempt budget within the original evidence limit.

Before each native request the prefix verifies the exact locked queue/item,
whole original authority ledger, immutable input files, verified prefix index,
actual current native source/tick/actor/clock and next tile's effective profile.
The original batch source is read explicitly as AUTHORITY, never represented as
the current native state. The actual fresh hash enters the original execution
request; compiled command source and authority remain bound to their original
batch. The generic readiness source gate is not relaxed or extended.

## Observation And Settlement

Reuse the original per-step after artifact and receipt metadata. Observe BEFORE
any existing early-stop branch, so a blocked suffix or exhausted attempt budget
cannot omit an actual action. The shared native boundary/selected-slot resource
validator verifies every observed success and no-effect failed suffix before
the next dispatch. A failed validation retains the original native verification,
request journal and after artifact, labels the owned prefix unverified, clears
candidate completion and stops before a second request or settlement.

Full/partial completion still reconstructs the original complete proof and
supporting-transition request. Only the verified consumed prefix is charged;
the growing crop is not cancelled. Lost mutation replies use the original
lookup, not resend. Other roots and the original persistent invariants remain
fully checked. Completion seals and matches every observed typed step, terminal
hash/tick and guarded after-file hash, not only the successful step count.
No further dispatch is admitted after sealing. An unverified first native attempt
remains incomplete with held resources for the original recovery owner; it is
never relabelled as the zero-native controller-stop diagnostic.

A controller stop BEFORE any native dispatch is a separate unchanged-preparation
diagnostic. It has zero actual attempts and zero step results, unchanged source,
ticks and after artifact, explicit stop reason/index/path, false freshness/success
and unchanged full marker readback. It neither invents a failed native action nor
produces a native proof, settlement, Teacher label or training authorization.
Plain and content-addressed after artifacts use the existing verified reader.
