# Rusty Key Native Terminal Source

Current criterion-local acceptance is tracked in
[local acceptance](rusty-key-local-acceptance.md). The terminal-source producer's
scope and false Teacher/formal-training claims below remain unchanged.

## Scope

`RustyKeyNativeKeyReceiptBuilder` turns one retained, attributable native key
transition into a source-rebuildable receipt. It adds no executor, acquisition
planner, learner ranking, preference label or game mutation. The existing
`GrandpaDirectionDailyCandidateBinding` remains the only owner of Rusty Key event
attribution; the original candidate generator and compilers remain unchanged.

The resulting `rusty_key_native_key_receipt.v1` verifies only the conditional
native key terminal, before exclusive total day 224. It does not certify the
preceding sixty-item supply, a fresh-save trajectory, Teacher comparisons,
train/validation/test coverage, an executable root or formal training.
`teacher_comparison_verified`, `full_criterion_verified` and
`formal_training_authorized` are always false. A later corpus must consume
`Verify`, not deserialize a receipt and trust its claimed booleans.

## Inputs And Rebuilding

The request is `rusty_key_native_key_receipt_request.v1`, with explicit `run_id`
and absolute paths in `action_queue_path`, `execution_receipt_path`,
`before_snapshot_path` and `after_snapshot_path`.

For a runtime priority interrupt, use that action's actual compiled queue and
actual before snapshot. In `rk-e8d7a6c3-1104`, these are
`interrupt-compiled-queue-0001-item-0002.json` and the preceding connector's
`after-snapshot-0001-item-0001.json`. The aggregate episode's earlier queue-start
snapshot has a different purpose and remains unchanged. An aggregate before
cannot replace the action boundary merely because both belong to the same run.

The builder requires explicit source schemas, observed game ticks, readable
actor/save identities, valid current-or-supported-legacy state hashes, matching
game/bridge versions, increasing ticks and one readable Stage-1 total day.
Missing or mistyped dates are not defaulted from unrelated fields.

Current `story.advance_event` availability is regenerated with an empty baseline
report, not Student weights or recorded selection. The original public direction
binding must return one attributable candidate; its original daily-plan and
action-queue compilation must succeed. The captured queue must bind that exact
candidate, state, actor and native action. Scoped Rusty Key and the two canonical
Grandpa goal IDs are accepted; unrelated goals are not. Event parameters and
compiled step semantics must match rebuilding. Generated step IDs and optional
budget annotations are not falsely treated as event semantics. Extra story
response parameters, stale fingerprints, changed steps and conflicting values
are rejected.

The immutable native receipt must bind the exact run, queue, item and before
state, with verified event completion, `native_event_input_only`,
`skipEvent_not_used` and exact event-66/event-seen facts. The following snapshot
must show the actual key false-to-true transition, unchanged donation count,
applied native museum prerequisite/reward, the native key event seen, Farm
location and closed event/control state.

Retained Live action receipts also carry `after_state_hash`, `before_game_tick`,
`after_game_tick` and `after_snapshot_fresh`. These application-layer fields are
read from the original JSON, not discarded by the base `TrainingExecutionResult`
deserializer. They must exactly bind the supplied snapshots and a fresh capture.
The PR #433 P2 finding was reproduced before the fix: a later same-state tick
was accepted. Eight new cases now reject that substitution, changed after-state,
wrong/missing/mistyped recorded boundaries and a stale capture. The original
Live writer and aggregate semantics were not changed; optional `actual_ticks`
is still not made mandatory.

The original story executor intentionally does not populate optional
`actual_ticks`. This consumer does not invent that requirement or rewrite old
receipts. Freshness is proved by the explicit before/after snapshot ticks and
source/receipt bindings. The initial local consumer incorrectly required the
optional field; real retained input exposed that assumption and the new
consumer was corrected. No old executor bug or new native run is claimed.

The result retains five source SHA-256 values, actual queue/item/state identity,
actor/save/version and observed day/ticks. `Verify` rebuilds all inputs and
compares the raw persisted JSON, including read-only claims. A forged true
Teacher claim cannot disappear through deserialization defaults.

## Commands

```powershell
dotnet <bootstrap.dll> build-rusty-key-native-key-receipt --request <request.json> --output <receipt.json>
dotnet <bootstrap.dll> verify-rusty-key-native-key-receipt --receipt <receipt.json> --output <replay.json>
```

Neither command launches a game, calls an executor/API, changes source artifacts
or authorizes training. CLI outputs stay outside Git. No Bootstrap-to-Live
reference was added; Live already depends on Bootstrap.
