# Original Crop Watering Maintenance Boundary

## Scope And Existing Implementation

PR528 accepted original route compilation/execution ownership on the existing
persistent crop owner. This successor consumes **original watering outcomes**;
it is not another watering executor or a complete maintained/saved crop cycle.
The original control compiler, refill planner, native WaterAfterRefill movement,
tool lifecycle and native sleep/save implementation remain unchanged.

`CropTeacherWateringMaintenance.Open` takes the original run request, current
accepted full source/ledger, active covered commitment identities and an original
`crop_actions` transition. It requires the current original watering obligation,
one1-8-item homogeneous batch, unique original layout targets and exact original
action commitment identity. Original target parsing is reused; it does not invent
an alternative coordinate/location parser or relax the seed planting deadline.

## Shared Evidence And Rebind

The existing completed-route source validation, fresh physical/logical CAS guard
and marker/reply replay are extracted for actual use by both consumers. Their
original route error/default semantics are preserved. Changing a CAS blob behind
an unchanged manifest or warm caller materialization still fails at a durable
boundary. No clock/source hash is rewritten to continue an old owner.

`CropTeacherAppliedPrefixReceipt` is the original planting receipt kernel with
primitive identity/diagnostic label supplied explicitly. Planting keeps its old
wrapper, primitive, predicates and error text, including incremental prefix use.
The original native step actor/source/tick/day/clock checker is also shared.
The full-success path still uses the original `QueueExecutionReceiptValidator`.

Only a verified applied prefix receives watering credit. A blocked suffix can
leave the exact unchanged target, or an independently accounted empty-can refill;
it never earns crop credit. Unknown/zero-applied or otherwise unsupported outcomes
are not silently treated as a completed batch. All actual retained step-after
files are absolute, unique, receipt-local, non-reparse and pinned, with exact chain
identity and final-after equality. A summary success flag alone is insufficient.

The original marker service only rebinds the accepted source; no material/currency
claim is consumed or other root re-labelled. The complete original marker reply
is independently replayed against the actual after before a consumer may advance.
The public result returns detached inputs/ledger/request and immutable applied
tiles; full crop-cycle completion and formal training remain false.
