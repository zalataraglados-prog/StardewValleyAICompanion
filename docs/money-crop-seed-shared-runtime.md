## One Transaction Owner

`CropTeacherSeedRuntimeTransaction` is extracted from the accepted purchase
runtime, not a second implementation of its retry/readback state machine.
The public purchase options and Prepare/Validate/Complete methods remain thin
adapters with the original schemas, filenames, statuses and behavior. Deferred
request readers retain the original artifact guards at mutation boundaries.

The transfer adapter supplies its immutable domain verifier to this same owner:

1. Read the complete current base ledger and compare it with the bound source.
2. Write the original commit journal, submit preparation once, and recover a
   lost reply only through original durable mutation lookup.
3. Independently replay the complete real preparation reply at its actual
   timestamp, then read back the complete prepared ledger before compilation.
4. Compile the verified marker through the original small-model queue endpoint,
   bind full queue JSON and physical SHA, and validate again before execution.
5. Consume the original native queue receipt. Rebuild the accepted transfer
   proof and send the original journaled supporting-transition settlement.
6. Replay the complete settlement reply and read back the complete final ledger.

Transfer never runs the purchase-only acquired-seed commit: its seeds already
have an owner. All destination partitions and passively compacted other-owner
claims remain governed by the original accepted kernel. No claim is minted,
silently cancelled or released by the runtime adapter.

Each completion object permits one attempt. Failures preserve phase-specific
diagnostics, preparation and native artifacts for original-journal recovery;
they do not retry mutations or roll back partially applied native execution.
An existing evidence directory rejects another preparation. Outputs remain
create-new; logical queue equivalence across encoding is distinct from the
physical SHA of the actual dispatched queue.

compilation still waits for a real verified preparation reply and full readback;

runtime interface: validate before its existing executor, then complete after
