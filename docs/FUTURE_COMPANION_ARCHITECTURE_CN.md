# StardewAI 未来陪玩架构约束

来源：用户桌面 `stardewai_未来规划，修正部分.txt` 与后续已经固定的产品动机。本文件记录会影响当前接口、训练和未来 Product/Companion 层的不可返工约束；未确定的体验参数仍保留为后续规格，不在当前阶段猜值。

## 产品终点

StardewAI 的终点不是“最会赚钱、最会下矿的自动化 Agent”，而是一个能与玩家从新存档 Day 1 起长期共同生活的 AI 伙伴。

核心体验目标：

- **共同在场**：玩家是玩家，AI 是另一个真实存在并能行动的角色；
- **连续记忆**：AI 记得共同发生过的事情，而不是每轮重新变成客服式聊天；
- **低审判反馈**：陪伴、解释和建议不能自动变成 KPI、监工或人生评价；
- **真实共同经历**：AI 通过原版世界状态、原生机制和自己的行动形成经历，不以直接改结果状态伪造“陪你玩过”。

因此“完美策略基线”只是 Companion 的一个底座，不是产品本身。后续 body、memory、persona、LLM interaction 和 multiplayer 不能因为策略训练推进而被误删或降级为可选演示。

## 联机角色边界

- 支持玩家开房后由本机后台 AI 角色加入、AI 主持后玩家加入，以及未来服务器托管角色加入三种模式。
- 三种模式共用原生多人游戏规则、同一高层策略接口和角色状态合同，不得为任一模式另写一套直接改游戏状态的执行器。
- AI 角色必须拥有独立输入通道，不能抢玩家键鼠、焦点或菜单控制。
- 多角色协作必须记录物品归属、玩家保留资源、任务分工、交换请求、暂停/打断和时间片状态。
- 玩家打断、拿走资源、改变地图状态或自己完成目标后，AI 必须 fresh replan；这些外部变化不能被错误记成策略模型的负奖励。

## 策略、技能与人格分层

- 完美策略、执行熟练度、知识可见度、交流主动性、合作关系、个人偏好和“装作新手”的提问/学习比例必须是彼此独立、可版本化的轴。
- 完美策略基线先冻结；拟人化、有限非最优、语气和声音只能作为可关闭的适配层，不能污染最优训练标签。
- 当前正式训练只学习“在透明状态和合法候选中现在做什么”；WASD、寻路、菜单、工具、战斗微操和原版时序继续属于确定性 Compiler / Product Executor。
- `PlayerCommandOnly` / delegated skill 不应因为“AI 会执行”就混入自主策略训练。染色、明确装饰命令、破坏性请求、真实完美小游戏代打等可以在核心训练之后独立补齐。
- 引擎选择保持可插拔；不同大小或供应商模型共享同一输入字段、候选 option 和结果记录合同。
- 不依赖大模型的简单量化沟通协议必须保留，供调试、低成本运行和无网络降级使用。

## 长期记忆边界

- 策略轨迹、执行回执和 Companion 长期记忆是三种不同数据，不得混成一个日志库。
- 策略训练只消费经过准入和验证的决策数据；Executor 失败/玩家打断不得污染 strategy value。
- Companion memory 可以记录“我们今天做了什么、聊了什么、发生了什么”，但不能反向伪造 TransparentBridge 事实。
- 记忆必须带 save / actor / date / provenance / version，支持遗忘、摘要、冲突修正和长期压缩。
- 人格层不能改写历史事实；它只决定表达方式、关注点、主动性和偏好。

## 能力扩展接口

- 保留零帧、瞬移等作弊能力，但只能进入显式测试/彩蛋 profile，绝不能混入合法训练样本。
- 预留类似技能 MOD 的扩展清单：扩展声明所需透明字段、输出 option、编译器能力、执行器能力和训练记录版本。
- 高技能 AI 可使用未来事件预测，但所有预测必须与实时事实分栏，并记录预测方法、置信度和失效条件。
- 位置口语理解、玩家临时参数注入、主动对话、物品交换和合作任务都必须先归一化成类型化合同，再进入动作编译器。
- Minigame Skill 可独立训练和替换。AI actor 不可见的街机玩法允许已明确授权的 `timed_equivalent` 作为自主策略机械层；玩家明确要求“帮我原生代打/全成就”时必须走真实本地 Skill Runtime、原生输入和原版状态机，不得把 equivalent 冒充 native perfect evidence。

## 完美基线后的目标扩展

爷爷 21 分是第一套长期评测目标，不是最终能力上限。后续目标至少包括全技能、社区中心/路线收集、全部星之果实、钥匙、矮人语、书籍与物品代取、高级机器、工具等级、附魔及全收集。临时语言模型只能选择或参数化这些目标，不得绕过透明字段和编译校验。

正式训练的里程碑必须分开写：

1. 单目标 Product episode 闭环；
2. 连续多日；
3. 跨季；
4. 跨年；
5. 独立 Year 3 / Grandpa 21；
6. 更广泛长期目标；
7. Companion body/memory/interaction 集成后的 E4。

前一项通过不能自动宣称后一项完成。

## 当前训练阶段反向约束

- 当前 r25 已证明真实 Product 轨迹能够生成正式 dataset 和 checkpoint 更新，但只完成有界单目标闭环；不得把它写成全量长训完成。
- 训练数据的版本、missingness、长期回报、崩溃恢复、磁盘保留和数据规模必须先于无人值守长跑得到严格门禁。
- `docs/FORMAL_TRAINING_BUG_FORECAST_20260901_CN.md` 中的主动静态发现属于风险/源码审计，不是 E3；需要运行复现的条目不能提前记为 runtime_verified。
- 长期计划必须持久化并可修订，机器前瞻建设、跨季备种和建筑扩建不能只存在于单日日计划文本里。
- 状态/输出记录必须带角色 ID、控制模式、策略 profile、人格 profile、引擎版本和扩展清单版本。
- 执行失败、玩家打断和资源被玩家先取走必须触发刷新重排，不得作为策略目标的负奖励。

## 发布定义

真正的 stable 1.0 不是“动作表 100%”或“策略 checkpoint 已生成”。至少需要：

```text
长期策略稳定
+ 独立 AI body / farmhand
+ Companion memory / persona
+ Player Language / IntentMediator
+ 玩家委托与自主生活共存
+ 多人/打断/恢复
+ 安装/配置/升级/诊断
+ 长时间 E4
```

如果最终只得到一个极强的 Stardew Valley automation framework，而没有共同在场、连续记忆和长期共存体验，则工程成功但产品动机没有完成。
