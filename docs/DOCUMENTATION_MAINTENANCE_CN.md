# 文档编辑与交接规范

本规范适用于仓库内的项目文档、专题证据说明和交接记录。先从 [文档总目录](DOCUMENTATION_INDEX_CN.md) 找到该问题的现行来源，再编辑对应文档。一个结论只在它的归属文档完整维护，其他入口使用链接或短摘要。

## 文档归属

| 内容 | 更新位置 | 同步位置 |
| --- | --- | --- |
| 当前在做什么、当前阻塞、下一步和恢复点 | [CURRENT_WORK_CN.md](CURRENT_WORK_CN.md) 顶部追加带日期的接续条目 | 如果结论或下一步变了，更新 [CURRENT_STATUS_CN.md](CURRENT_STATUS_CN.md) 对应状态和入口 |
| 当前覆盖数字、验收状态、施工优先级 | [CURRENT_STATUS_CN.md](CURRENT_STATUS_CN.md) | 同步当前工作；引用当前机器报告或对应提交，不沿用历史数字 |
| 训练准入、Provider、覆盖层级或产品阶段 | 对应的正式准入、Provider、R2 或产品合同 | 若改变当前执行顺序或读者应先看的入口，同步当前工作、当前状态和总目录的现行入口／时间关系 |
| 某项设计、实验、原生证据、失败复盘 | 对应专题文档或证据账本 | 只有影响当前结论、风险或下一步时，才同步当前工作或当前状态 |
| 原始存档、运行日志、反编译与私有制品 | 按 [制品布局](knowledge-artifact-layout.md) 管理 | 文档写工件索引、哈希和可重放条件；仓库只收既定范围内的可公开摘要和证据 |

## 什么时候同步总目录

- **新增、移动、重命名或删除文件。** 同一提交或 PR 内新增、更新或移除全量目录的对应条目，并检查其他文档的旧链接。条目总数变化时同步目录数量。保留原始日期依据。新文档可在标题写明正文日期，或直接以本次提交的北京时间登记。
- **文档改为历史、被另一份合同取代，或现行入口发生变化。** 在原文档中追加可见的失效说明及 `audit_invalidation` 注释，并在总目录的「现行入口」或「关键时间关系」同步替代关系。只有某一节失效时写清该节，不把整份文档标为失效。
- **有会改变后续工作的新裁决。** 写入归属文档并从当前工作和当前状态链接过去。跨专题或改变读取优先级的裁决，同时补入总目录的关键时间关系。单项试验记录留在对应专题。
- **普通正文修改。** 错字、链接修复、解释补充和范围内的补测直接改归属文档。全量目录日期记录的是文档时点或首次入库时点，后续编辑无需刷新日期。

## 追加与失效

当前状态、计划或验收口径改变时，先追加新条款，再紧邻旧段落注明其适用范围。保留历史测试结果和旧失败。可以修正格式与错误链接。若原始结论有误，用新结论、证据和失效说明保留追溯关系。

时间戳使用北京时间 `YYYY-MM-DDTHH:mm:ss+08:00`。新条款记录核对的 commit／PR、事实与决策、证据链接和适用范围。待合并的修订注明合入后生效，日期只表示记录时间。以下示例中的占位符由编辑者替换。

```markdown
<!-- audit_invalidation: scope=<旧段落或条款>; invalidated_at=<带时区时间>; superseded_by=<新文件及锚点>; reason=<具体失效原因>; historical_only=true -->
> **<时间> 失效说明。** <哪些旧口径被取代、哪些证据仍可复用>。现行规则见 [<标题>](<相对链接>)。
```

## 交接记录

### 能力块与持续阻塞

持续卡住且没有新事实或实质进展时，先回看最新用户目标、现行下一步、原退出条件和旧实现的提交／上下文；区分真实缺口、新消费者不兼容旧合同、夹具／环境错误与控制端施加的资源限制。不能默认旧执行器有错，也不能通过不断增加验证条件替代完成目标。真实运行中的可观测推进不算反复卡住。

以一个完整能力块连续负责实现、范围内调试、针对性回归和集成为单位。普通编译、断言和夹具错误在原块内修复，不为每个小错新建任务、会话或整套交接；只有模块／所有权／接口边界变化时才换完整交接包。协作者的源码只读依赖按模块在调用前一次核对，写、运行、秘密和清理权限仍分别受限。已有通过证据复用，接受标准保持原业务语义；这条经验不新增审计／验收阶段，也不承诺不会出错。

经用户授权的常驻合作按同一能力块的实质进展续接，不套用临时补丁worker的一次修正计数。已实现的部分保留，未完成部分以简短增量接续；不得反复重建上下文或只为确认规则单独付费调用。额度／provider失败立即停止且不自动换源；重复无进展则先校准目标、原合同和环境限制，不能以“常驻”为理由无限空转。

在现有 `CURRENT_WORK_CN.md` 追加短条目即可。需要保存完整原生证据、复杂分支或独立交接包时，再使用专题文档并链接。避免为同一工作维护两份「当前下一步」。交接应让接手人能从准确的恢复点继续。

1. **身份与范围。** 记录北京时间、分支／commit／PR、正在处理的目标和选中路线。有实机证据时再给游戏、SMAPI、平台及 run/save/actor 身份。
2. **已完成与证据。** 分别写实现、测试夹具、原生验收、独立重放和正式准入状态。给出产物索引与 SHA-256。若原始工件在外部，写明取用范围和校验方式。证据缺失标为未判定。
3. **未完成与首个阻塞。** 记录确切失败阶段和可复现输入。中断时标明最后持久保存点、可复用工件、未保存尾部和相关进程状态。历史运行、模拟和正式数据分别登记。
4. **下一步与退出条件。** 写一个可执行的接续点及验证方式。标出当事决定的适用范围，说明哪条旧口径失效。当前状态、覆盖或授权有变化时同步归属文档。

## 提交前核对

PR 正文引用未完成的 issue 时只写“仍在跟踪”等普通引用，不把关闭关键字与编号相邻，即使句子是否定句。2026-11-12 的 #555 因此误触自动关闭 #339，已按事件归因修正文案并恢复跟踪；这不代表验收完成。真正结束 issue 时应先核对其完整退出条件，再使用关闭关联或显式操作。

合并命令、发布核验和 Git 引用清理分开执行，不能在未检查上一条返回结果的批次中连续运行。任何合并、网络或树比对失败都立即短路。清理前独立读取远端 PR 的 `MERGED` 状态及 merge commit，确认最终已验 head／主线内容树一致、被删引用恰为自有已合入 head。严格 base 规则要求更新祖先时先重验当前 head。2026-11-12 #558 曾因合并被拒后仍继续删除引用而被误关，引用和同一 PR 已恢复、按新 head 正式合入，提交／内容树未丢失；初次失败不能被记录为合并成功。

新增或移动文件先暂存，再在仓库根目录用 PowerShell 检查全量目录是否漏项、重复或保留了旧路径。对新增相对链接和标题锚点另做核对。

```powershell
$tracked = @(git ls-files -- docs '*.md' '*.markdown' '*.rst' '*.adoc' '*.txt' | Sort-Object -Unique)
$entries = @(Select-String -LiteralPath docs/DOCUMENTATION_INDEX_CN.md -Pattern '^\| \d{4}-\d{2}-\d{2} \| \[(?<path>[^\]]+)\]\(' |
    ForEach-Object { $_.Matches[0].Groups['path'].Value })
$duplicates = @($entries | Group-Object | Where-Object Count -gt 1)
$difference = @(Compare-Object -ReferenceObject $tracked -DifferenceObject @($entries | Sort-Object -Unique) -CaseSensitive)
if ($duplicates.Count -or $difference.Count) {
    $duplicates | Select-Object Name, Count
    $difference
    throw '文档总目录与 Git 文件清单不一致。'
}
git diff --check
if ($LASTEXITCODE -ne 0) { throw '工作区差异检查失败。' }
git diff --cached --check
if ($LASTEXITCODE -ne 0) { throw '暂存差异检查失败。' }
```

合并前核对 PR 中的历史记录、状态和工件范围。工程证据和启动授权继续按各自合同处理。
