## Existing Rules And The New Consumer

Old social candidates deliberately leave remote immediate stand coordinates
empty (`08c31fcf6`), compile one connector and refresh before continuing
(original tests `44b9f5c00`). A bounded retained-JSON lookup did not recover that
discussion; the source and original tests establish the contract. These are not
executor bugs and were not changed. The default 64-candidate source budget,
original Teacher/itinerary, strict binder, native actions and compilers remain.

The new read-only `CurrentSocialRouteContactBudgetBuilder` adapts that contract
for independent comparison. It creates the original current contact frontier,
loads the original calibration and date/route context once per builder, and
reuses `FutureRouteDateEvidenceProducer.RequiredFirstEdge` and
`NpcFutureContactWindowResolver`. It adds no pathfinder or native executor.
It owns only the needed route JSON fields and source identity, not the full
raw snapshot, and can finish its proof after the caller disposes that document.

Each budget binds the raw snapshot identity, exact candidate/continuation/NPC,
authoritative contact window, gift resource when applicable, actual first edge
and complete route through native gates to an adjacent stand. The first edge
must include its source/arrival coordinates and match the original graph.
An unrelated optimal route, equal connector count or only the first-leg cost
cannot supply the full contact budget. The proved stand stays in the new budget
record, not in the old candidate's remote immediate fields. Native execution
still receives one original connector and must fresh-rebind before interaction.

Only original frontier objects with unchanged captured fields are accepted;
foreign, injected or edited windows fail. Missing/invalid raw schema, tick,
hash, timing, route, permission or remote tail cannot borrow legacy defaults.
Complete route requests cache by source-local request/opportunity identity,
including the actual first edge; changing it cannot reuse another proof.
The comparison rejects routed rows without a matching complete contact proof.

Preference artifacts are v3. Earlier v1/v2 diagnostics remain retained and are
not silently upgraded; public Verify rebuilds the entire artifact from the
original raw sources. Immediate comparison, original dispatch compilation and
full-order eligibility semantics are unchanged by this slice.
