## Original Contract And Explicit Scope

The original [independent pairwise admission](independent-teacher-pairwise-admission.md)
and actual `StructuredPolicyTrainer.BuildPairs` consume only explicitly replayed
strict pairs in the full candidate context. They do not convert all other
choices into negatives. The new Friendship consumer had coupled every usable
pair to a complete order; this slice separates those claims without changing
the old trainer, Teacher proposal, comparison criteria, binder or executor.

The preference schema is now v4. Old v1/v2/v3 artifacts remain retained and must
be rebuilt from their original sources, not edited or silently upgraded.

| Claim/mode | Contract |
| --- | --- |
| `IndependentPairwiseLabelEligible` | At least one original strict pair after complete-source, original-control, contact/binding/compiler checks. |
| `TeacherPreferenceLabelEligible` | The original complete-order condition, including zero required-but-uncompared alternatives. |
| Default / `--admission complete_order` | The original complete-order refusal remains. |
| Explicit `--admission independent_pairs` | Only the proved pairs can admit the original selected control; all unknown/tradeoff choices stay unlabeled and retained. |

Build and Verify accept that optional mode solely to select the exit gate; both
emit the same complete, deterministic artifact. Its general `status` and
`blockingReasons` still describe the default complete-order gate. The separate
pairwise flag/scope records why explicit pair consumption may be allowed even
when that default status remains blocked. Missing or unknown evidence, no strict
pair, source truncation, ambiguous available identities and native safety failures
are not rescued by this mode. This is not a global ordering or training permit.

`FriendshipTeacherDispatchBuilder.Compile(path)` retains its original signature
and default. The typed overload accepts `IndependentPairs` only when explicitly
chosen. Both rebuild through the same Verify and use the same original plan and
action-queue compilers. Stored eligibility flags are never sufficient. Unknown
CLI mode names and undefined enum values are rejected before reading evidence
or creating dispatch files. There is no second executor or comparison policy.
