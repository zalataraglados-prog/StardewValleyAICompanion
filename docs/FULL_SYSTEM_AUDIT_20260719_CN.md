# StardewAI 全量复盘（2026-07-19）

## 1. 结论

当前项目不是“什么都没开始”，也不是“已经可以正规训练完全体”。它已经形成一条可工作的 C# 主链：实时透明快照 -> 候选生成 -> 日计划 -> 动作编译 -> 原生执行器 -> 前后状态与训练样本。仓库注册了 86 个 option，当前 Core 和 Backend 单元测试规模分别为 1034 和 63。

但 option 注册、静态编译通过、运行时实现、真实游戏验证、可用于策略训练是五种不同完成度。当前主要成果集中在透明读取、机械动作编译、若干原生执行器和隔离运行验证；真正的小模型仍未接入。`BaselineFeatureRowTrainer` 只按 option 聚合标签，`LiveTrainingLoop` 仍使用 mock、参数化动作或基线排名，不是已训练策略模型。

因此结论是：机械执行底座已经很宽，但全量策略训练仍应暂停。现在最有价值的工作不是继续增加松散 option，而是补齐会导致训练返工的长期承诺、库存/产能和运行验证缺口。

## 2. 当前机器模块

爷爷策略方向的当前正确口径是 **11/11**：旧交接曾把 `complete_joja_development` 作为第 12 个方向，但它只是社区中心评分因子的互斥替代路线，不是独立评分方向，现已从目录删除。11 个正式方向均有直接绑定；这只代表策略入口覆盖，不代表其所有下游执行闭环均已完成。

机器不再按设备名称固定分级，而按当前需求流动态标记：

| 标记 | 当前触发依据 | 例子 | 当前状态 |
|---|---|---|---|
| `factory_scale_batch` | 当前兼容存货 + 已种或明确承诺的连续收获波 | 蔓越莓到果酱、草莓批处理 | 已覆盖当前背包、当前机器、已种作物和版本化室外跨季作物承诺；其他未来供给仍未覆盖 |
| `workshop_scale_recurring_or_bounded` | 无作物波但有当前待加工存货 | 蛋奶、矿石、前期煤炭 | 已覆盖当前背包的有界服务；每日动物产出和未来采矿计划未覆盖 |
| `collection_scale_one_off` | 普通任务、特别订单、浣熊请求或首次制作 | 熏鱼机处理当前浣熊请求、Craft Master | 任务和当前原生浣熊请求已覆盖；其他全收集承诺仍需统一目标账本 |

当前判断会计算：当前存货单位、保守原生周期、同类机器数量和忙碌剩余时间、下一次已种作物收获、到达前可处理量、缺口、需新增数量、最晚有用建设窗口。过早建设会输出 `deferred_too_early_machine_would_idle`，而不是进入候选。

上游排除的精确定义：没有当前任务；覆盖范围内没有产能缺口或尚未到最晚建设窗口；该配方已经完成首次制作。任一事实不完整时应阻塞并暴露原因，不能把“不知道”当作“没有需求”。

当前模块的硬边界：种子库存不等于未来种植承诺。第二年春一计划种多少草莓、第一收日期、取消/改种，必须来自版本化策略承诺账本。机器投影只消费有效版本；即使作物尚未进入背包，也只会依据完整原生机器触发规则静态证明加工能力。带动态条件、自定义输出方法或缺失时长的规则继续 fail closed。

## 4. 已有真实运行证据

仓库 `artifacts` 中可见的近期隔离产物包括：普通矿洞深度链、骷髅洞竖井、运输、原生社交、鱼塘、淘盘、动物产品、蟹笼、钓鱼，以及较早的机器收取/装载、作物、巨型作物和掉落拾取。

这些产物证明对应窄切片可以通过原生游戏路径执行，不证明整个域已经完成。文档中写明“static executor complete / runtime pending”的部分不得进入高置信策略标签。

## 5. 正规训练前 P0 缺口

2026-07-19 进展：第 1 项的室外季节作物切片已经完成，包含持久化、修订/取消/完成历史、原生目录绑定、无库存时的原生机器触发证明、连续再生波次吞吐和编译器版本漂移阻塞。第 2 项已完成静态统一物资图首版：玩家背包、跨持久化地点的玩家箱、当前玩家冰箱、全局箱去重、Workbench 连接边、自动采集器及机器 ready/in-process 缓冲区都能追溯到节点和槽位；精确槽位预留投影会阻塞重复、漂移和超额。第 4 项的作物再生部分已进入统一容量方程。复盘同时修正了机器透明摘要的原生 1.6 类型边界：`MachineOutputRule.OutputItem` 按完整列表读取，触发条件保留在 trigger 行，机器级额外消耗/计时修改/暂停条件不再错误归到规则级；动态计时与额外供给未承诺时 fail closed。物资图仍缺隔离游戏快照验证和原生箱子转运执行；这些进展也不代表动物、矿石、鱼塘、蟹笼和广义长期目标已经完成。

1. **版本化长期承诺账本**：记录作物/地块数/种植日/预计收获波、动物与建筑计划、加工目标、采购与全收集目标、来源决策、修订和取消。它是策略输出，不从库存猜测。
2. **完整物资与容量图**：玩家背包、所有玩家拥有的箱子、冰箱、Workbench 连接库存、自动采集器及机器在制品必须形成统一、无重复的可用量和预留量。当前静态图和精确槽位预留投影已实现并通过离线测试；隔离快照、原生转运和多人资源归属策略仍未完成。
3. **机器建设闭环**：需求 -> 材料取得 -> 原生制作 -> 选址 -> 原生放置 -> 装载/收取 -> 路线维护 -> 扩容/迁移。当前读和制作较强，放置与长期服务仍未闭合。
4. **重复供给投影**：已种再生作物的连续收获、每日/隔日产物、矿石冶炼队列、鱼塘/蟹笼等必须使用同一时间轴，避免只看当前背包。
5. **透明字段门禁自动化**：每个模型可选 option 必须声明所需字段、字段状态、反编译证据、运行验证和输出记录路径；缺一项就不能进入策略训练集合。
6. **真实模型 provider 与评测**：替换 mock/基线聚合器，冻结 schema/option/编译器/执行器版本，先做离线合法率与回放，再做隔离存档短闭环，最后才做长时训练。

## 7. 建议实施顺序与退出条件

1. **承诺账本**：草莓/蔓越莓等跨季例子能产生可修订的收获波；退出条件是机器投影只消费明确承诺且能识别取消。
2. **库存图**：所有玩家拥有存储的数量和预留无重复；静态退出条件已满足，同一物品总量和预留可审计回具体容器/槽位。完整退出仍要求隔离存档覆盖普通箱、全局箱、冰箱、Workbench、自动采集器和机器缓冲区，并验证多人归属不会误用玩家保留资源。
3. **机器闭环**：完成制作、放置、服务和迁移；退出条件是隔离存档可从缺机状态自动建设并完成一批加工。
4. **重复供给**：作物再生、动物和矿石队列进入同一容量方程；退出条件是工厂/作坊规模不会随快照抖动且不过早闲置。
5. **全 option 门禁报告**：自动生成每项 read/candidate/compile/runtime/output 状态；退出条件是不存在未声明字段和无证据训练项。
6. **模型接入**：先结构合法性 SFT/分类，再策略训练；退出条件是模型输出只选择上游合法候选，编译阻塞率和执行失败率达到冻结阈值。
7. **完美策略基线后拟人化**：速度、失误、知识、话语和合作偏好作为独立 profile/checkpoint；不得污染完美策略语料。
