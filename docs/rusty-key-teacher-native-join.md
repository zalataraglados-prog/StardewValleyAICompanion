# Rusty Key Teacher / Native Causal Join

## Scope And Claims

`RustyKeyTeacherNativeJoinBuilder` connects an independently rebuilt threshold
donation comparison to an exact same-run native key outcome. It is not another
planner, action executor, candidate ranking or training entry point.

It verifies one conditional 59-to-60 decision, the native reward, uninterrupted
mechanical continuation, one normal native-save-ready sleep and the later key
terminal before exclusive total day 224. It does not prove sixty-item supply,
global end-of-night controller handoff, fresh-save completion, all three data
partitions, an executable root or formal training. The corresponding full
criterion, threshold supply, global night handoff and formal-training flags
remain false. No coverage counter or checkpoint is promoted by this producer.

## Rebuilding And Source Binding

The request schema `rusty_key_teacher_native_join_request.v1` contains
`comparison_path`, `native_key_receipt_path`, and an ordered `actions` array.
Each action supplies `action_queue_path`, `execution_receipt_path` and
`after_snapshot_path`. The before snapshot is obtained from the original
verified native request journal, not chosen independently by the caller.

The existing comparison and native key verifiers must rebuild their original
inputs. The donation must be one of that independent comparison's strict
preferred alternatives, with the same pre-decision file hash, state, tick,
actor, goal and original compiled native command. Control selection identifies
which preferred action was actually executed; it never defines a preference.

Every action must bind its original request journal, nonce, wire-body hashes,
queue/item identity, actor, native executor, save isolation and exact recorded
before/after frames. The shared DTO's JSON field names identify wire parameters;
declared queue values must match the actual native RPC payload, including
missing-field rejection. This is a verifier, not a second request compiler.
Nonces and queue/item identities cannot repeat. Adjacent snapshots must have
identical boundary state hashes and ticks. Different versions, actors, dates,
endpoints, isolation roots, unrecorded gaps and unrelated actions are rejected.

The current original option registry owns behavior/responsibility/training
classification. Sleep remains `recovery`, not `mechanical`. The new consumer's
initial all-mechanical assumption was corrected using real retained input; no
old sleep behavior or classification was changed. The recorded mechanical
queue path has precedence over a parent effective-plan path for interrupts.
Caller-supplied queues and after snapshots must be those recorded action files.

Donation binds the exact item false-to-true museum transition, one-item native
inventory consumption, original native menu completion facts and the observed
duration within the comparison's 600-update horizon. The later
`daily_plan_time_budget_checked` planning-only proof marker and optional budget
annotations are not falsely compared as native action changes. All other
command semantics and safety constraints remain checked. The old data is not
rewritten to acquire a newer annotation.

Native connectors and bounded waits require their original completion facts.
Sleep consumes its immutable per-action native-save-ready result, exact day
change, saved/new-day/control-restoration facts and next-day snapshot. It does
not reinterpret the later mutable global night transaction as a new success.
The existing broader PowerShell night checker and its contract remain intact.
The exact terminal action/files must match the separately verified key receipt.
Optional story `actual_ticks` is not made mandatory. Aggregate queue-start
semantics remain unchanged; only actual per-action boundaries are consumed.

## One Journal Reader

The original bounded gzip/SHA/metadata/payload verification kernel is now in
`StardewAI.Core.Infrastructure.ExecutionRequestJournalReader`. Live's original
`RuntimeExecutionRequestJournal.ReadAsync` public signature remains a thin
compatibility wrapper. Writer, record format, exact body bytes, product hash,
8 MiB limit and schema are retained. This avoids both a Bootstrap-to-Live cycle
and a copied journal validator. Original dispatch/read tests and additional
tampering cases exercise the same reader used by the join.

## Commands And Replay

```powershell
dotnet <bootstrap.dll> build-rusty-key-teacher-native-join --request <request.json> --output <receipt.json>
dotnet <bootstrap.dll> verify-rusty-key-teacher-native-join --receipt <receipt.json> --output <replay.json>
```

The result retains source hashes and ordered native action identities. Replay
rebuilds the entire comparison/source/key chain and compares raw persisted
JSON, including get-only claims. A consumer must call `Verify`, not deserialize
and trust a claimed true field. The split is always the original donation
decision's `save:player:day`, never the later key-event day.
