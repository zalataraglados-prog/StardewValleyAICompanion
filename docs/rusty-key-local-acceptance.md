## Method Responsibility Reconciliation

The old dependency prose demanded a single minimum-time sixty-item portfolio.
That no longer described the approved
[rolling method](rusty-key-rolling-supply.md#scope-and-reuse): a currently legal
one-item step may proceed without routes for the other 59 items. The graph now
describes that same method, rather than leaving an implemented recurrence
marked as missing or inventing a second planner to satisfy stale prose.

- Preserve the complete 95-item authoritative denominator; stop at live 60.
- Reduce `max(0, threshold - donated_count)` by exactly one per verified distinct
  donation. Acquisition alone does not count as donation progress.
- Reuse the original joint resource preflight, output custody, authorized
  storage/withdrawal, route/opening/time budgets and fresh replan boundaries.
- A requested full-threshold certificate still needs exactly the entire live
  deficit. A partial proposal cannot claim that certificate. The synthetic
  preflight suite now checks every below-threshold count 0 through 59, in
  addition to existing satisfied, invalid, overbooking and protection cases.
- Reuse native museum60 reward and event 66, with the existing source-bound
  comparison/native verifiers, original split function and coverage adapter.

This is conditional method implementation and local evidence readiness, not a
claim that greedy elapsed-time control is a global optimum. The corpus adapter
never bypasses method execution, independent comparison or native partitions.
Accepted Pet Love, Skull Key, custody and owner-visual gates are not reopened.
