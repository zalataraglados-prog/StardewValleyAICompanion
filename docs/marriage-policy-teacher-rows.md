## One Input Pipeline

`MarriagePolicyInputProjector` is shared by Teacher rows, structured Backend
inference and loop feedback. It requires readable current marriage/house facts,
inventory, and the original compatible route calibration. It reuses the existing
**contact-only** Friendship helper, not that goal's 1975-point/people threshold.
Current-contact certification belongs to the projection itself for every original
family, so callers cannot omit certification for non-gift candidates. IDs and
the original denominator remain intact; projection works on copies and never
injects model features into native action parameters. Only the reused native
contact admission may append its original provenance parameters; existing values
are retained, and projecting the result again is idempotent.

Shared features retain verified complete arrival budgets, native before/expected
relationship effects, current item sale value with an explicit known flag, and
the distinction between gift support and other original families. Missing prices
do not become free items. Snapshot-matched state features include house levels
missing, native construction days, engagement/roommate/joint/settlement facts.
The native `-1` construction marker is retained. Other goals keep prior features.
Feedback also checks the actual compiled queue goal and item identity.
